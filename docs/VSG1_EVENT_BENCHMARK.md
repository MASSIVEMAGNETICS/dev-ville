# VSG1 event-envelope benchmark (synthetic TRACE-0/Chronos schema)

**Scope:** a reproducible, standard-library-only comparison of **complete** Victor
TRACE-0 Informatron events and Chronos receipts. The fixture is generated by the
real `Trace0Observer` and `ChronosLedger` classes in `trace0_chronos.py`, with fixed
inputs, timestamp, and no real user or production data. It exercises the actual
hash-chain verification contract. The benchmark does not replace Chronos state.

**Provenance:** `MASSIVEMAGNETICS/dev-ville`, fixture schema from
`trace0_chronos.py` at commit
`f4d340c48d6b23af6bc708c45ece7872499c3273` (stacked PR #38 base).
The JSON report records the SHA-256 digest of the generated canonical corpus,
Python version, platform, and number of repetitions. It explicitly labels the
corpus `real_events=false`. Do not call these production or held-out results.

## Run

```sh
python -m unittest -v test_semantic_codec.py test_vsg1_event_benchmark.py
python vsg1_event_benchmark.py --records 128 --repeats 5 --output vsg1-benchmark-report.json
```

CI runs on Python 3.10, 3.11, and 3.12 and publishes a separate JSON artifact for
each environment. No network, third-party packages, model weights, or credentials
are required. The output file is optional; by default the JSON prints to stdout.

## What is compared

| Method | Encoding | Decoding |
| --- | --- | --- |
| `canonical_json` | Canonical JSON of full event+receipt records | Parse JSON, restore and verify Chronos chain |
| `zlib_json_9` | zlib level 9 over the same canonical JSON | Decompress, parse, restore and verify Chronos chain |
| `vsg1_full_record_adapter` | One triple per record; subject is event ID, predicate `chronos_record_json`, object is the **entire canonical event+receipt JSON**; then VSG1 | VSG1 decode, canonical record and subject checks, restore and verify Chronos chain |

All methods are measured end-to-end for encoding, and decoding **including
receipt-chain verification**. The VSG1 adapter is deliberately conservative: it
wraps complete records rather than throwing away sequence, provenance, evidence,
authority, event ID, or chain receipt. It is not a trained semantic encoder.

For each method report bytes, exact round-trip, verified Chronos chain, median
wall time, median process CPU time, and peak Python allocations (`tracemalloc`).
The VSG1/zlib size ratio is also reported; **ratio > 1 means VSG1 is worse**.
All timings are noisy and should be compared on the same hardware under repeated
runs. `tracemalloc` omits native zlib allocations. Process CPU time is **not**
an energy measurement.

## Verification and nonclaims

The tests reject subject tampering, receipt tampering, wrong predicates, and
noncanonical embedded JSON. All three methods must reproduce the identical full
record list and successfully restore the Chronos chain. The benchmark is not
proof of model tokenization savings, semantic accuracy, reasoning gains, or AGI.

**Next gate:** obtain a consented, scrubbed, provenance-labeled *real* Victor
corpus without private events, secrets, identifiers, or authority material; freeze
held-out splits and compare task accuracy and neural inference costs against a
conventional tokenizer. Do not upload raw production Chronos logs to this public
repository. Keep PR #36 and stacked security PR #38 behind independent exact-head
review and explicit merge authorization.

## Bounded baseline decoders

The canonical JSON and zlib(JSON) reference decoders now enforce the same
8,000,000-byte maximum uncompressed frame size as the VSG1 codec. The
zlib baseline additionally bounds compressed input using the zlib
`compressBound` formula, caps decompression output, and rejects truncated,
corrupt, concatenated, and trailing-byte frames. Canonical JSON must be
UTF-8, deterministic, and byte-for-byte canonical after parsing; duplicate
object keys, nonfinite constants, whitespace variants, and ambiguous
encodings are rejected. This is a benchmark safety gate, **not** an
authentication mechanism or a claim that all real-event JSON formats are
accepted. Baseline decoding now includes these validations in timing
measurements; compare fresh exact-head benchmark artifacts rather than
mixing timing results from earlier commits.

## Adversarial JSON nesting gate

Both the VSG1 structural decoder and the direct Chronos triple adapter now
convert Python JSON decoder `RecursionError` and `OverflowError` into
`ValueError`, preserving the public decoder's fail-closed error contract.
Regression tests supply a 12,000-level nested JSON input and require rejection
without an uncaught interpreter exception. This is an exception-boundary
hardening step, not proof of complete denial-of-service resistance. The VSG1
wire decoder remains bounded by its existing compressed/uncompressed limits;
the direct adapter should only receive trusted or separately size-bounded
inputs in production.

## Synthetic mission-disjoint holdout (evaluation scaffolding only)

For synthetic corpora with at least two 16-event missions, the benchmark report
now includes `evaluation_split`. It verifies the **entire** Chronos chain first,
then partitions by the synthetic mission `CONTAINS` edge. Groups are ranked by
SHA-256 of a fixed versioned salt and mission ID; the first ceil(25%) of mission
groups are held out. No mission appears in both train and test. The manifest
records group names, record counts, ordered event-ID digests, full-corpus digest,
and full-corpus chain head; it **does not** export event payloads.

For fewer than 17 records, the report marks the split unavailable rather than
inventing an independent group. The subsets are **not** individually valid
Chronos chains because the original hash chain spans the entire corpus.
`source_chain_verified` applies only to the original full corpus. The split is
reproducible and provenance-labeled, but it does **not** demonstrate
generalization, learned semantics, real-world privacy clearance, or neural
task accuracy. All events remain synthetic. No production event data are read.

The next real-data gate still requires affirmative authorization, an explicit
redaction policy, an independently retained checkpoint, and held-out task
labels established before training. Do not mistake a synthetic group split for
independent replication or a semantic benchmark.

## Pinned chain-head verification (synthetic fixture only)

All three benchmark decoders accept `expected_chain_hash` (64 lowercase
hexadecimal characters). The benchmark captures the fixture's Chronos chain
head **before** encoding and requires the restored snapshot to match that head.
An internally valid but different chain is rejected. Tests cover a wrong
snapshot, incorrect pinned heads, and the same acceptance gate across JSON,
zlib(JSON), and VSG1. Decode+verify timings include this check.

**Trust boundary:** the fixture head comes from the same synthetic generator,
not a separately authenticated authority. In real deployments, the expected
head must be supplied from a trusted, independently retained checkpoint or
signed receipt. A self-contained hash chain alone cannot prove who authored
it or prevent wholesale rewriting. This does not change Chronos authority,
execute actions, or authenticate real production data.

## Direct Chronos adapter input bounds

The public `from_triples` adapter now validates **each** input triple before
calling `json.loads`. It rejects more than 100,000 triples, invalid schemas,
non-UTF-8 strings, any field longer than 10,000 Unicode code points, and
aggregate UTF-8 triple-field content over 8,000,000 bytes. The limits are
aligned with the VSG1 wire codec's record and uncompressed-byte ceilings,
though wire framing adds separate overhead. This closes an earlier direct
Python-call bypass of the wire decoder's resource bounds. Tests cover
oversized fields, lone surrogates, excessive record counts, aggregate bytes,
and the existing deeply nested input. These checks bound *accepted* input;
they do not prevent a caller from allocating an oversized list or string
before invoking the adapter, nor prove immunity to all resource exhaustion.


## Train-only byte-pair vocabulary probe (synthetic, nonsemantic)

`vsg1_bpe_probe.py` is a bounded, standard-library-only **learned tokenization
probe**, not a learned semantic encoder. It verifies the complete Chronos chain
before applying the already preregistered mission-disjoint synthetic split.
A deterministic byte-pair vocabulary (maximum 128 merges) is fitted **only**
on training-mission canonical event+receipt documents; held-out missions never
participate in merge selection. Token IDs are 16-bit; the report includes the
full merge-table overhead (4 bytes per learned pair) plus zlib-compressed
token IDs and compares that total to zlib-compressed canonical held-out JSON.
The byte-token reduction is **not** a conventional LLM-tokenizer comparison.

```sh
python -m unittest -v test_vsg1_bpe_probe.py
python vsg1_bpe_probe.py --records 128 --merges 64
```

CI runs this probe on Python 3.10/3.11/3.12 and publishes the JSON alongside
the original lossless codec benchmark. The report records training and testing
corpus digests, full chain head, model size, exact held-out recovery, and
measured sizes. This is not a production wire codec; the compressed token
stream and merge table are a research cost estimate without a complete
authenticated envelope. The benchmark does not measure neural accuracy,
semantic similarity, or energy and cannot establish a token successor.
The original full Chronos chain is verified before splitting; split subsets
are not independently valid chains. The next research gate remains
independent exact-head review and a privacy-approved real-event corpus with
preregistered task labels and conventional tokenizer baselines.

### Serialized BPE frame recovery gate

The probe now reconstructs the 16-bit token stream from the **actual zlib
frame** and restores the learned merge table from its serialized 4-byte pairs
before checking byte-for-byte held-out recovery. Earlier results verified
in-memory tokens only; that was insufficient to establish serialized
reversibility. Four adversarial tests reject invalid merge references,
truncated/concatenated/trailing compressed frames, odd packed-byte counts,
invalid token IDs, and decompression expansion beyond 8 MB. This is still
an unauthenticated research format, not a production Chronos envelope.
